# Spec: Погодный SEO-кластер «Погода в Грузии»

_Составлено 03.09.2026. Метод: spec-driven + seo-cluster (hub-and-spoke, intent-класс, матрица перелинковки, анти-тонкий-контент)._

## Objective

SEO-кластер страниц о погоде Грузии по регионам и городам — канал органического трафика туристов на **этапе планирования поездки** («какая погода в X», «когда ехать в X»), с воронкой в туры. С учётом наличия ПФ целимся и в высокочастотные город-запросы, не только длинный хвост.

**Пользователь:** турист (РФ/СНГ), решает ехать/когда ехать до поездки.
**Успех:** кластер в индексе, растут позиции по «погода в {регион/город}», переходы погода→тур (utm), рост органики на планировании.

## Тех-стек

- Статический HTML (как весь сайт), генерация скриптом (по образцу `scripts/gen-blog.py`).
- `api/weather.js` — edge, Open-Meteo forecast (готов, без ключа, кеш 1ч).
- `scripts/fetch-climate.py` — разовый сбор климат-нормалей из Open-Meteo **archive** → `data/climate.json`.
- Индексация: sitemap + IndexNow + Google Indexing API (готовое).

## Охват первой волны (RU)

| Хаб | `/pogoda/` | 1 |
| Регионы | `/pogoda/{kakheti…}/` (11 папок сайта) | 11 |
| Города (все популярные) | `/pogoda/{slug}/` — Тбилиси, Батуми, Кутаиси, Казбеги, Местиа, Гудаури, Бакуриани, Боржоми, Сигнаги, Мцхета, Телави, Гори, Зугдиди, Кобулети, Уреки, Ахалцихе, Ананури, Вардзиа, Уплисцихе, Ушгули, Поти, Рустави, Кварели, Шатили, Омало (Тушети) … | ~25 |

Итого **~37 страниц** (RU). EN/GE — 2-я волна после валидации.

**Страницы краткие, но НЕ голый виджет** (голый виджет = thin content / doorway → фильтр Google, ПФ не спасает). Минимум уникального индексируемого ядра на каждой: климат-таблица (реальные цифры, статикой) + мини-текст + FAQ + live-виджет. Экран-полтора, не лонгрид.

**Регион vs город (анти-каннибализация):** регион-страница = обзор всего региона + ссылки на его города; город-страница = точечная погода города. Разный intent-таргет («погода в Аджарии» СЧ ↔ «погода в Батуми» ВЧ), взаимные ссылки, свои canonical.

## Данные (оба источника)

1. **Live-виджет** (JS): `api/weather?region=X` — сейчас + 6 дней. Свежесть, причина вернуться. Не критично для индекса.
2. **Климат-таблица 12 месяцев** (СТАТИКА в HTML — индексируется): °C день/ночь, осадки, дни с осадками, [темп. моря для прибрежных], солнечные часы. Источник — **Open-Meteo archive, усреднение ~10 лет**. Реальные цифры, не выдумка.

## Шаблон страницы (анти-тонкий-контент)

1. H1 «Погода в {X}: по месяцам и на неделю»
2. Live-виджет (сейчас + 6 дней)
3. Климат-таблица 12 месяцев (статика)
4. «Лучшее время ехать» + **абзац от гида Тимура** (уникальный опыт по региону — E-E-A-T, чего нет у Gismeteo)
5. «Что делать в это время» → связанный тур + CTA
6. FAQ (schema FAQPage): «когда лучше ехать в {X}», «погода в {X} в [месяц]», «холодно ли зимой»
7. Перелинковка: соседние регионы/города + хаб
8. Schema: Place/WebPage + FAQPage + BreadcrumbList; связь с TouristTrip тура

**Хаб:** сетка регионов с live-мини-t°, таблица «когда куда ехать» (сезон × регион), ссылки на все страницы, сезонный обзор Грузии + CTA.

## Матрица перелинковки (mesh)

- Хаб → все регионы + топ-города
- Регион → хаб, соседи, свои города, тур(ы) региона
- Город → хаб, свой регион, соседние города, тур города
- Обратно: **на КАЖДОЙ тур-странице блок «Проверить погоду» → соответствующая погодная страница** (двусторонняя связь погода↔продажа; передаёт вес новому кластеру от авторитетных тур-страниц + UX «проверь погоду на дату»)

## Code Style / генерация

- Данные (координаты, климат, тексты гида, связка тур↔регион) — в JSON/словаре, шаблон отдельно (как `gen-blog.py`).
- Тексты гида — **уникальный абзац на страницу** (пишутся, не клонируются — иначе тонкий контент). 22 абзаца.
- CSS — переиспользовать стили регион-страниц + минимум для виджета/таблицы.

## Testing Strategy

- `node scripts/predeploy-check.js` по образцам страниц перед деплоем (обязательно по CLAUDE.md).
- Ручная проверка: live-виджет тянет данные, климат-таблица заполнена реальными числами, все ссылки живые, hreflang/canonical корректны.
- Проверка индексации после деплоя (GSC/IndexNow ответ).

## Boundaries

- **Always:** predeploy-check перед деплоем; climate-данные из archive (не выдумывать); раздел в футер, НЕ в шапку.
- **Ask first:** деплой; добавление в главную навигацию; месяц-спицы (2-я волна); EN/GE.
- **Never:** трогать `main.js`/существующие регион-папки/`vercel.json` редиректы; выдумывать климат-цифры; ломать sitemap.

## План (этапы)

1. `scripts/fetch-climate.py` → `data/climate.json` (реальные нормали, 22 точки).
2. `api/weather.js` — добавить города в REGIONS.
3. Шаблон + генератор; собрать **прототип: хаб + Кахетия** → показать (не деплой).
4. После ок — 22 абзаца гида + генерация всех 22 страниц.
5. sitemap + индексация + predeploy + деплой (по команде).
