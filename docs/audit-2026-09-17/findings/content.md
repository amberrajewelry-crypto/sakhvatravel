# Content Quality / E-E-A-T Audit — sakhva-travel.com
Дата: 2026-09-17. Метод: curl (raw HTML) + stdlib-парсинг текста, sitemap-N.xml, content_quality.py (ограниченно — токенайзер плохо работает с кириллицей, low-signal, не основной источник). crawl.json от оркестратора не появился за отведённое время — оценка построена на прямой выборке 21 страницы.

## Итоговый балл: 78/100

Сильная сторона — реальный E-E-A-T (именной гид, WhatsApp/Telegram, честный рейтинг, FAQPage-схема, вариативный шаблонный контент с реальными данными). Слабые места — риск каннибализации между landing-страницами городов и /tury/, отсутствие автора/схемы Person на части страниц, часть страниц ниже топикал-минимума.

## Doказательства по разделам

### 1. Идентичность автора и опыт
- /about/: title "Тимур — авторские туры и экскурсии по Грузии", h1 "Гид в Тбилиси — Тимур Сахвадзе", desc "500+ туров, рейтинг 4.9/5 по 90+ отзывам" — 1235 слов, JSON-LD содержит `Person`, `Review`, `FAQPage`.
- Упоминания "Тимур" по страницам: главная 24, /about/ 15, /contacts/ 7, туры-экскурсии 6-11, блог 5-9, **/en/ — 0 упоминаний имени гида** (десктоп EN 2862 слова, но без персонализации — это ослабляет Experience/Trust для англоязычной аудитории).
- pogoda/* — только 2 упоминания Тимура (шаблонная плашка со ссылкой на "Экскурсию в Кахетию"), это нормально для weather-utility страниц, но делает их E-E-A-T нейтральным, не поддерживающим бренд.

### 2. Рейтинг/отзывы — честность консолидации
- Заявлено "рейтинг 4.9/5 по 90+ отзывам" на главной и /about/.
- Слово "отзыв" встречается на 15 из 21 просмотренных страниц (то есть виджет отзывов подключён широко) — это хорошо для консистентности сигнала, но нужно **выборочно проверить**, что AggregateRating/Review JSON-LD не задваивает один и тот же пул на каждой странице тура искусственно (риск за пределами curl-выборки, требует ручной сверки чисел в разметке против реальных 90 отзывов).
- /en/: рейтинг встречается (4.9 ×2, reviews ×4), но без имени гида — England-версия слабее по Experience-сигналу.

### 4. Дублирование / шаблонность (pogoda, страны)
- pogoda/kakheti/ vs pogoda/imereti/ структурно идентичны (одинаковые блоки: "Прогноз погоды по дням", "Погода в N по городам на неделю", "Климат N: чем отличаются города", "Чем заняться в N по сезонам") — **но переменные данные подставлены корректно** (разные города, высоты, температуры: Телави +27°/Тушети +20° vs Кутаиси +29°/Чиатура +28°). Это программатик-паттерн приемлемого качества (см. seo-programmatic для полного стандарта), не спам, т.к. каждая страница несёт уникальные числа и локальные факты, плюс CTA на конкретную экскурсию отличается по региону.
- Риск: если у Google/Яндекса появится сигнал "шаблон на 66 страниц pogoda/*" без углубления (нет реальных допданных типа влажности, UV, локальных примет) — стоит добавить хотя бы по одному уникальному факту/совету от гида на регион, чтобы не консолидировалось в "thin doorway pages".

### 5. AI-цитируемость (Sept 2025 QRG / AI Overviews)
Сильно:
- FAQPage JSON-LD подтверждена на /about/, /ekskursiya/art-tur-tbilisi/, /pogoda/kakheti/, /tury-v-gruziyu-iz-kazani/, /voprosy/ — прямые Q&A блоки хорошо цитируются AI Overview/ChatGPT.
- Конкретные цифры-факты в title/desc: "от ₾98", "500+ туров", "рейтинг 4.9/5 по 90+ отзывам", "Летави +27°/Тушети +20°" — годятся как прямые quotable-факты.
- Понятная иерархия h1→разделы (заголовки "Климат N: чем отличаются города", "Чем заняться в N по сезонам") — хорошо для экстракции сниппетов.

Слабо:
- /en/ не содержит структурированного FAQ по выборке (не проверено JSON-LD на этой странице — стоит проверить отдельно, т.к. это международная точка входа).
- Нет видимых Table-блоков (напр., таблица "город — сезон — цена") в просмотренных турах/лендингах — списки текстовые, а не HTML `<table>`, что снижает шанс попадания в табличные AI-выжимки.

### 6. Каннибализация ключевых слов
- `/tury-v-gruziyu-iz-kazani/` и `/tury-v-gruziyu-iz-voronezha/`: заголовки/дескрипшны хорошо различены городом-отправления, оба ссылаются на общий каталог `/ekskursiya/` и `/tury/` (перелинковка верная, не дублируют коммерческий intent между собой). Риск каннибализации **между landing "tury-v-gruziyu-iz-X" (124 URL в sitemap-landing.xml) и хабом /tury/ + /tury-v-gruziyu/** реален на уровне запроса "туры в грузию" в целом — 124 гео-лендингов + главный хаб могут конкурировать за одинаковые нецелевые ("туры в грузию" без города) кластеры, если внутренняя перелинковка/канонические теги не разграничивают intent строго по городу вылета. **Рекомендация:** проверить canonical и intitle-разметку на выборке 5-10 landing-страниц, чтобв убедиться, что title всегда включает город-отправления (в осмотренных двух — да, "из Казани"/"из Воронежа" присутствует).

## Fixes (приоритет)
1. Добавить 400-500 слов на /blog/chaevye-v-gruzii/ (сравнение по типам заведений, личный кейс гида, таблица "заведение — % чаевых") — закрывает и thin content, и AI-цитируемость.
2. Добавить 100-150 слов на /voprosy/ (ещё 2-3 частых вопроса).
3. Внедрить имя гида + короткий authority-блок на /en/ (сейчас 0 упоминаний "Timur").
4. Проверить canonical/hreflang на выборке 10 landing-страниц из sitemap-landing.xml — исключить самоканнибализацию с /tury/.
5. Проверить GSC/Search Console на 404-паттерны типа /pogoda/<city>-<day>-<month>/ и /kontakty/, /strany/* — при наличии внешних ссылок/старых URL настроить редиректы.
6. На pogoda/* добавить 1 уникальный тезис от гида на регион (лайфхак/примета), чтобы застраховаться от consolidation risk на масштабе.
7. Перевести 2-3 ключевых текстовых списка (цены/сезоны) в тур-страницах в HTML `<table>` для лучшей AI-выжимки.
