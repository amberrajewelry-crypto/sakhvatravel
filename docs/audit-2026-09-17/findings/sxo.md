# SXO Gap Score: 56/100 — sakhva-travel.com

## Метод и ограничения
- Рендер только статичный HTML (curl --compressed), без Playwright/скриншотов — позиции элементов на странице определены по доле байт от начала `<body>`/H1 до начала документа (`hero-h1`→конец), это ПРОКСИ для scroll-depth, не точный пиксельный замер. Считать «≤2 скролла» ≈ первые 15-20% тела документа.
- SERP снят через WebSearch (сниппеты + AI-обзор Google), не сырой HTML топ-10 — типы страниц классифицированы по названию/описанию домена, без чтения самих страниц конкурентов.
- Число органических результатов на запрос — 8-9 (WebSearch лимит), а не полные топ-10.

## Главный вывод: структурный mismatch — единственный бренд vs маркетплейс

Sakhva — легитимный **single-vendor tour operator** (как advantour.com, coolgeorgia.com, allgeotrip.ru, delicatours.ge — они тоже ранжируются). Это НЕ доменная ошибка. Но для 3 из 6 запросов Google системно вознаграждает **маркетплейсы** (Sputnik8, Tripster, GetYourGuide-класс, ToursByLocals, GoWithGuide) — они физически не могут быть скопированы одним брендом: сотни гидов, сравнение цен, отзывы на КАЖДОГО гида, сетевой SEO-вес доменов. Для операторских запросов (конкретный тур/направление) Sakhva УЖЕ в правильном формате.

## Почему хорошо оптимизированная страница всё равно проигрывает агрегатору
1. **Объём предложения.** У Sputnik8/Tripster 700-890 вариантов туров на кластер —長-tail покрытие Sakhva физически не достижимо одним доменом.
2. **Социальное доказательство на уровне позиции, не бренда.** Агрегатор показывает рейтинг и отзывы у КАЖДОГО гида в выдаче/на странице — у Sakhva рейтинг один на весь бренд (см. AggregateRating в схеме — есть, но не факт что визуально в hero, см. ограничения).
3. **Доменный авторитет сети.** Sputnik8/Tripadvisor — DR 80+, тысячи referring doamins; у одностраничника такого не будет никогда за счёт on-page.
4. **Мультиязычный/мультигеографический масштаб контента** — у агрегаторов тысячи лендингов "экскурсии в X из Y", у Sakhva — десятки.

Вывод: **не пытаться обыграть маркетплейсы в лоб на "экскурсии тбилиси"/"гид в тбилиси"/"private tour guide tbilisi"** — это структурно проигрышная битва. Инвестировать в запросы, где сам формат "один оператор" уже побеждает (операторские intent-запросы вида "[тур] из тбилиси", "[направление] экскурсия", тур-специфика, погодный/travel-utility контент с мостиком к бронированию).

## Быстрые фиксы (по убыванию влияния)
1. **Pogoda-страницы = верхняя воронка без монетизации.** Добавить в первый экран (не 46%!) блок "Ищете тур в это время года? [Казбеги/Кахетия туры] от ₾X" — сейчас это чисто информационная утилита, теряет trial-конверсию на самом дешёвом по CPC трафике. → см. `/seo page` для аудита конкретных pogoda-урлов.
2. **Нет лендинга "гид в Тбилиси"/EN "private tour guide tbilisi".** Создать отдельную страницу-профиль гида (не общий каталог) с фото, именем, лицензией, отзывами именно на гида — единственный шанс частично закрыть mismatch HIGH по этим 2-3 запросам без превращения в маркетплейс.
3. **Тур-страницы длинные — "Включено"/отзывы после условных 2 скроллов.** Поднять блок "Включено/Не включено" и первый отзыв в верхнюю треть страницы (сразу под ценой и CTA), не в середину.
4. **E-E-A-T на homepage.** Если AggregateRating виден только в JSON-LD, а не визуально в hero — добавить видимый бейдж "4.9 ★ (N отзывов)" рядом с ценой в hero (сейчас это не подтверждено скриншотом, риск).
5. Не гнаться за "экскурсии тбилиси"/"гид в тбилиси" в лоб контентом — вместо этого удвоить операторские long-tail (уже работающий формат, см. Казбеги/винный маршрут).
